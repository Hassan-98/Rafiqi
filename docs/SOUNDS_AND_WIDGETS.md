# Notification sounds & home‑screen widgets

Developer notes for two features:

1. **Per‑type notification ringtones** (Makkah adhan for prayers + a distinct tone per reminder type, with an in‑app picker).
2. **Android home‑screen widgets** (next prayer, prayer times, daily progress, tasbeeh).

---

## 1. Per‑type notification ringtones

### How it works

Android freezes a notification channel's sound at **create** time, so each distinct ringtone needs its **own channel**. The single source of truth is:

- [`src/services/notifications/sounds.ts`](../src/services/notifications/sounds.ts) — the `SoundKey` set, the `SOUND_DEFS` registry (file, channel id, importance, Arabic labels), the per‑category defaults (`defaultSoundForKey`), and the picker list.
- [`CapacitorNotificationService`](../src/services/notifications/CapacitorNotificationService.ts) creates **one channel per sound** on `initialize()` and routes each notification to the channel matching its `soundKey`.
- Schedulers ([prayer](../src/services/PrayerTimeNotificationScheduler.ts), [fasting](../src/services/FastingReminderScheduler.ts), [islamic](../src/services/IslamicCalendarScheduler.ts)) and the [notification store](../src/store/notificationStore.ts) pass a `soundKey`. The in‑app picker is [`SoundPicker.tsx`](../src/components/settings/SoundPicker.tsx), wired into Settings.

Default mapping: prayers → `adhan_makkah`; pre‑adhan / iqama → `adhan_short`; azkar → `azkar`; Qur'an wird → `quran`; qiyam → `qiyam`; fasting → `fasting`; du'a → `duaa`; habits → `habits`; Islamic‑calendar days → `special`. Users can override any of them per‑category in **Settings → التنبيهات** (tap the ♪ chip on a row, preview, pick).

### Which sounds are real vs. placeholder

- **Real recordings (mp3):** the call-type sounds use genuine audio — `adhan_makkah.mp3` (full Makkah adhan) for the five prayers, and trimmed real takbeer clips for `adhan_short.mp3` (pre-adhan/iqama), `tone_fasting.mp3` (fasting), and `tone_special.mp3` (Islamic days). Sourced from islamcan.com's free adhan library; replace with your own licensed recordings for distribution if needed.
- **Synthesized placeholders (wav):** the gentle reminder chimes — `chime_azkar.wav`, `tone_quran.wav`, `tone_qiyam.wav`, `chime_duaa.wav`, `chime_habits.wav` — are generated by [`scripts/gen-notification-sounds.mjs`](../scripts/gen-notification-sounds.mjs) (`npm run gen:sounds`, which skips the four real recordings). Swap any of them for real audio via the drop-in steps below.

### Drop in real audio (e.g. a genuine Makkah adhan)

1. Put your file in **both** locations, keeping the **same filename**:
   - `android/app/src/main/res/raw/adhan_makkah.wav` — the real on‑device ringtone.
   - `public/sounds/adhan_makkah.wav` — the copy used only by the in‑app **preview** button.
2. Re‑build: `npm run android:build` (or `npm run build && npx cap sync android`).

Filenames per type live in `SOUND_DEFS` in [`sounds.ts`](../src/services/notifications/sounds.ts): `adhan_makkah.mp3`, `adhan_short.mp3`, `tone_fasting.mp3`, `tone_special.mp3` (real), plus `chime_azkar.wav`, `tone_quran.wav`, `tone_qiyam.wav`, `chime_duaa.wav`, `chime_habits.wav` (placeholder chimes).

**Using an MP3 instead of WAV:** Android raw resources support `.mp3`. Drop `adhan_makkah.mp3`, then change that entry's `file:` in `sounds.ts` to `'adhan_makkah.mp3'` and bump `CHANNEL_VERSION` (next point).

> ⚠️ **Android freezes channel sound at create time.** After changing any sound file *content under a new name* or a channel's importance, bump `CHANNEL_VERSION` in `sounds.ts` (e.g. `v4` → `v5`) and add the old channel ids to `STALE_CHANNEL_IDS`, otherwise existing installs keep the old frozen sound. Replacing a file **with the same name** is picked up on reinstall/clear‑data; the version bump guarantees it for everyone.

To regenerate the placeholder tones: `npm run gen:sounds`.

## 2. Android home‑screen widgets

Seven widgets under `android/app/src/main/java/com/darkmon/myzikr/widget/`:

| Widget | Class | Shows |
| --- | --- | --- |
| Next prayer | `NextPrayerWidget` | The top of Home's prayer card (PrayerHero) + a **live countdown** (Chronometer, API 24+) |
| Prayer times (4×3) | `PrayerTimesWidget` | Home's whole prayer card: countdown, the five prayers (a due one logs on tap → queued `prayer.toggle`), «من ٥ فروض» |
| Calendar (4×2) | `CalendarWidget` | Home's «اليوم في التقويم» card: Hijri medallion, dates, occasion chips, the next occasion |
| Today's prayers (4×2) | `TodayPrayersWidget` | «صلوات اليوم»: fard + أذكار counts, countdown, five prayers — a due node logs the fard (`prayer.toggle`), its «أذكار» pill marks the adhkar (`prayer.adhkar.toggle`, which also logs the fard) |

These four are **painted replicas** of the Home cards (`widget/CardPainter.java`: Canvas + the app font Alan Sans from `res/font`, measured from the web layout) — RemoteViews can't use custom fonts (TextView skips font resources in the launcher's restricted context). Only the countdown is a live Chronometer laid over its painted slot. Edit the cards and CardPainter together.
| Daily progress | `ProgressWidget` | A ring of today's overall worship completion |
| Tasbeeh | `TasbeehWidget` | Quick tap counter (+1 / reset) |
| Today's tasks (2×2→4×4) | `TasksWidget` + `TasksWidgetService` | Scrollable list of today's tasks; tick box toggles instantly (queued `task.toggle`), title → task, «+» → add sheet |
| Next lesson (3×1) | `StudyWidget` | Next/live study session, countdown within 24h, «افتح الرابط» (ACTION_VIEW, http/tg/whatsapp/zoom only) |
| My day (4×2) | `DashboardWidget` | Next prayer countdown, progress ring, tasks done/total + shortcuts: time-aware أذكار, قيام الليل, القرآن, التسبيح |

### Data bridge (web → native)

The WebView can't share `localStorage` with native code, so the web app writes a compact JSON snapshot to **Capacitor Preferences** (`@capacitor/preferences` → SharedPreferences file `CapacitorStorage`, key `widget_snapshot`):

- Writer: [`src/services/widgetBridge.ts`](../src/services/widgetBridge.ts) (`startWidgetBridge()` is called from [`main.tsx`](../src/main.tsx); it writes on store changes, every 60 s, and when the app backgrounds).
- Reader: `widget/WidgetData.java` parses the same key.
- Refresh: widgets update on their 30‑min cadence, on tap, on the next‑prayer rollover alarm, and `MainActivity.onPause()` calls `WidgetUpdater.updateAll()` so they refresh when you leave the app.

The tasbeeh widget's counter is native‑only (its own SharedPreferences) so it works without launching the app; tapping its dhikr name opens the in‑app tasbih screen.

### Build & test

```bash
npm run android:build          # build + sync + assembleDebug
# or just compile the native side after a web build:
npm run build && npx cap sync android && \
  android/gradlew.bat -p android assembleDebug
```

Then long‑press the home screen → **Widgets** → **مَوْقِظي** to place them. The next‑prayer / prayer‑times widgets need a location set in the app (otherwise they show "حدّد موقعك في التطبيق").

### Notes / future work

- Deep links: `WidgetUpdater.openRoute(ctx, req, "/route")` sends an explicit ACTION_VIEW `com.darkmon.myzikr://widget/#/route` to MainActivity → Capacitor `appUrlOpen` → main.tsx navigates to the hash (cold + warm start).
- Task ticks: appended to Preferences `widget_pending_actions` (protocol in widgetBridge.ts); `WidgetData` overlays pending toggles on the snapshot so a tick survives the app's 60 s snapshot rewrite until the app drains the queue on resume.
- Title taps inside the task list go through a broadcast trampoline (collections allow one PendingIntent template) — relies on the launcher's click granting the activity start.
- Live countdown uses `Chronometer` countdown (API 24+); on API 23 it falls back to a static "بعد … " label.
